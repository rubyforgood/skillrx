Record page: the "Record" card

A provider's page today has a right-hand card titled "Record" holding three database fields: when the row was created and last updated, and its ID. It stretches to the height of the left column, so three small facts sit in a tall, mostly empty card with the same weight as the real details. The same card is on the user and beacon pages. Two ways to fix it; A is recommended.

1Timestamps and ID are a quiet line, not a card

"Added", "Last updated" and "ID" describe the database row, not the provider. They go in one small gray line under the content, as GitHub, Linear and Notion show "created" and "edited". Still there for support and audits, without a card of their own.

Today: a full card on the right with the same weight as Details.

2A side column only for real secondary content

A uses one column at reading width: this record has four facts and a list of people, not enough to fill two. B keeps two columns but puts the related people on the right, the way Stripe and Shopify Polaris use a sidebar. Either way cards align to their tops and don't stretch to match.

Polaris: use the two-column layout only when there's secondary information to put in it.

3"13 topics" links to them

The count opens the topics list filtered to this provider, which the list already supports. A count you can't follow is a dead end.

Small extra, same change.

4Type is said once

The type showed twice: under the name and as the first row of Details. It stays under the name, where it identifies the provider, and leaves Details. It shows as entered ("ngo"); it's free text, so the app doesn't recase it.

Small extra, same change.

Where it applies

  • Providers (providers/show): as previewed.
  • Users (users/show): the same Record card beside Access. Same fix: a quiet line under Access.
  • Beacons (beacons/show): its right column also holds the API key, which is real secondary content, so the two columns stay; only the Record card becomes the quiet line.

design.md's "Record pages" section would get the rule: row metadata is a quiet line, never its own card.
